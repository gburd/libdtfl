## notify_multiworker: Counter drops a flush (fixed, c2e9f74)
#
# Property: tests/pbt/pbt_ops_notify.c notify_multiworker.
# Found by: make check-sim with DTFL_PBT_FLUSH_STEPS=on, hegel 0.36.5.
# Minimal case: 2 simulated workers, seed 0, no faults; worker 0 sends
# one record at epoch 1, flushes, steps once, closes.  The run never
# completed and stopped at the simulator's step cap.
# Cause: the pinned timely Counter forwards a flush only while its
# produced batch is undrained (dev/upstream-notes.md, "Counter drops a
# flush once its produced count is drained").  Reproduces on real
# threads (DTFL_PBT_COMM=process hung) and in Rust at timely 0.31.0 and
# on timely master; reported upstream as timely-dataflow issue #824.
# State: fixed in c2e9f74, a deliberate divergence (ADR-0012,
# 2026-10-23): the Counter also forwards a flush when it pushed data
# since the last one.  The flush draw is now on by default, so check-sim
# covers it.  Expected now: REPLAY PASS.  Checked both ways: REPLAY FAIL
# ("simulation made no progress after 2000001 steps") before c2e9f74,
# REPLAY PASS after.
notify_multiworker DTFL_PBT_FLUSH_STEPS=on DTFL_PBT_COMM=sim DTFL_PBT_FAULTS=on DTFL_PBT_ONLY=notify_multiworker DTFL_PBT_REPLAY=AXiczcoxCgAACAJAbewd/f+NCU1B1JqDh2BAcapYoGHLGuF9eUUC8LABtw== tests/pbt/pbt_ops_notify

## fuzz_ddir_parse, fuzz_ddir_value: DDIR panics on bad names (open)
# dtfl_ddir_parse aborts through the panic hook on a program that
# lowers badly, e.g. the 12-byte pipe program  export "" = t;
# ("unresolved name `t`"), and on unknown scopes, unknown outer names
# and cyclic lets.  dtfl_ddir_value_parse aborts on a closed term that
# names a variable, e.g. ^5 ("Bound(5) out of range"; before a5ef099
# it read out of bounds).  These are upstream's own panic!s
# (interactive/src/lower.rs, eval in ir.rs at
# differential-dataflow-v0.25.1); upstream's ddir_server catches them
# with catch_unwind, which C does not have, so dtfl_ddir_parse is
# documented to return an error but does not.  The fix is to turn the
# lowering and evaluation panics into dd_parse_error-style unwinds that
# return DTFL_EINVAL.  Also open: parse_pattern_case leaks its scratch
# vectors when a parse error unwinds mid-arm (documented in
# src/ddir/parse_pipe.c).  No reproducer is committed to the corpus,
# because make fuzz must replay it clean.

## fuzz_diag_replay: signed overflow in the diagnostics stats (fixed)
# The in-process diagnostics server and dtfl-diag arrangements and
# profile summed stat values, merge lengths and elapsed times from a
# recorded stream in int64_t, and negated a Drop length, so a hostile
# stream was C signed overflow (UBSan src/diag/diag_log.c:93 and :322).
# Upstream's isize arithmetic wraps in a release build; it now wraps
# here.  Found 523 times in the 45-minute campaign; all 523 replay
# clean after the fix.  Checked both ways.
fuzz_diag_replay tests/fuzz/fuzz_diag_replay $(top_srcdir)/tests/corpus/fuzz/fuzz_diag_replay/regress-stat-overflow
fuzz_diag_replay tests/fuzz/fuzz_diag_replay $(top_srcdir)/tests/corpus/fuzz/fuzz_diag_replay/regress-negate-min
