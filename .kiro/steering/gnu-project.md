# libdtfl: GNU project conventions

Use this for build system, packaging, documentation and release work.

## Build system

- Autoconf and Automake with Libtool, using a non-recursive top-level
  `Makefile.am` (one Makefile, with `include` fragments per directory).
- `./bootstrap` runs `autoreconf -fi`.  The generated `configure` is not
  committed (AGENTS.md section 8).  It ships in the tarball.
- The library version comes from `configure.ac`
  (`AC_INIT([libdtfl], [x.y.z], ...)`).  The libtool `-version-info
  C:R:A` follows the libtool rules and is bumped only at release.
  Symbols are versioned through `src/libdtfl.map`.

### Configure switches

| Switch | Effect | Default |
|---|---|---|
| `--enable-debug` | debug asserts, owner-thread checks, leak checks | off |
| `--enable-asan`, `--enable-ubsan`, `--enable-tsan` | sanitizer flags | off |
| `--with-hegel[=PREFIX]` | enables the property-test tier | off (property tests report SKIP) |
| `--disable-diag` | omits the WebSocket diagnostics | enabled |
| `--disable-ddir` | omits the DDIR interpreter | enabled |
| `--disable-server` | omits the `dlopen` plugin server | enabled |

### Make targets

- `all`, `check` and `install`, plus the standard GNU directory
  variables.
- `check-asan`, `check-tsan`, `check-interop`, `fuzz`, `bench`.
- `doxygen`, `pdf`, `html`, `info`.
- `distcheck` must pass at every phase exit.

`make clean` never deletes `dev/`, `doc/` sources or `tests/corpus/`.

## Files every GNU package has

- `README`: what it is, how to build, where the manual is.
- `NEWS`: user-visible changes per release, newest first.
- `ChangeLog`: generated from git into the tarball.  The repo carries
  a stub pointing at `git log`.
- `AUTHORS`.
- `THANKS`: upstream authors and contributors.
- `COPYING`: MIT, plus the upstream notices verbatim.
- `INSTALL`: generated by automake.

## Documentation

### Texinfo manual

- The manual is `doc/libdtfl.texi`, with one included file per chapter
  under `doc/timely/` and `doc/differential/`.
- Code samples are real files under `doc/snippets/`, pulled in with
  `@verbatiminclude`.  `tests/dist/test_docs.sh` compiles and runs
  every snippet against its `.expected` output.
- The manual describes what the code does now.  It does not narrate
  the port history.

### Man pages

Man pages are written in mdoc(7) under `man/man{1,3,7}/` and installed
by automake.

- **Section 3:** one page per function family.  The page lists every
  `.Nm` it covers, and each covered name is installed as a link to the
  page.
- **Required sections:** NAME, LIBRARY, SYNOPSIS, DESCRIPTION, RETURN
  VALUES, ERRORS, THREAD SAFETY, EXAMPLES, SEE ALSO, HISTORY.
- **HISTORY:** names the upstream Rust item the function ports.
- **Lint:** every page must pass `mandoc -Tlint`.  `test_docs.sh`
  checks this when mandoc is installed, and reports SKIP otherwise.

## Prose

Follow the maintainer's prose rules in all shipped text (manual, man
pages, NEWS, commit messages):

- two spaces after a period;
- no em dashes;
- plain register;
- describe the code as it is.

## Releases

- Versioning is semantic: `0.y.z` until 1.0 (PLAN section 13), when the
  ABI freezes.
- Make the tarball with `make distcheck`.  Tag `vX.Y.Z` (annotated) on
  the commit that produced it.
- Write the release notes in `NEWS` first.  The tag message is the
  NEWS entry's first line.
- The release qualification lists which verification tiers ran (PLAN
  section 6) and which platforms were tested.
